# ثبت منابع دادهٔ NetGuard

این فایل فهرست اولیهٔ منابع عمومی است. «قابل دسترسی بودن API» به‌تنهایی به معنی مجوز ذخیره‌سازی نامحدود، استفادهٔ تجاری، پوشش جغرافیایی ایران یا به‌روزرسانی لحظه‌ای نیست. هر adapter پیش از فعال‌شدن باید با محدودیت‌ها و مجوز فعلی آن منبع تطبیق داده شود.

## وضعیت منابع

| منبع | دادهٔ قابل استفاده | نقش در NetGuard | cadence اولیه | وضعیت |
| --- | --- | --- | --- | --- |
| IODA | سیگنال‌های سری زمانی، metadata، event و outage alert | منبع اصلی سیگنال‌های ملی | بررسی هر ۵ دقیقه؛ تازگی تابع upstream | فاز اول |
| RouteViews | BGP updates، وضعیت collectorها و آمار peering | پایش مسیرها و دیدپذیری BGP | بررسی هر ۵ تا ۱۵ دقیقه با توجه به دادهٔ منتشرشده | فاز بعد |
| RIPE Atlas | دادهٔ probeها و نتایج measurementهای عمومی | شواهد DNS، Ping، Traceroute و reachability | بررسی هر ۵ تا ۱۵ دقیقه، فقط برای measurementهای موجود | فاز بعد |
| OONI | metadata و نتایج آزمون دسترس‌پذیری/سانسور | شواهد تکمیلی محدودیت دسترسی | کم‌فشار؛ ابتدا روزانه یا چندبار در روز | فاز بعد |
| M-Lab | NDT، throughput، latency و داده‌های تاریخی | روند کیفیت اتصال و مقایسه‌های تاریخی | batch روزانه/هفتگی؛ نه منبع live | فاز بعد |
| Cloudflare Radar | آمار ترافیک و روندهای اینترنتی | زمینهٔ تحلیلی اختیاری | فقط پس از بررسی مجوز | فعلاً غیرفعال |

## 1. IODA — منبع اصلی فاز اول

- API رسمی: https://api.ioda.inetintel.cc.gatech.edu/v2/docs
- API شامل سری‌های زمانی، رویدادها، هشدارهای outage، metadata و اطلاعات منابع داده است.
- مسیر فعلی مورد استفاده در کد قدیمی مخزن، endpoint سری زمانی کشور برای کد `IR` است.
- سه سیگنال قدیمی مخزن: `bgp`، `ping-slash24` و `merit-nt`.
- پیش از فعال‌سازی مجدد باید شناسهٔ datasource، معنی واحدها، فاصلهٔ نمونه‌برداری، تأخیر انتشار، رفتار مقدارهای null و ساختار فعلی پاسخ با مستندات زنده API تطبیق داده شود.
- دادهٔ IODA بخشی از تصویر شبکه است و تجربهٔ مستقیم همهٔ کاربران یا تمام ISPهای ایران نیست.

## 2. RouteViews — شواهد BGP

- API: https://api.routeviews.org/docs/
- مستندات API اطلاعات collectorها و دسترسی به داده‌های BGP را توصیف می‌کند.
- مستندات فعلی، update dumpها را با دورهٔ ۱۵ دقیقه‌ای و metadata دسترس‌پذیری collectorها را با به‌روزرسانی سریع‌تر توصیف می‌کنند.
- RouteViews برای مشاهدهٔ تغییرات routing و بررسی شواهد BGP مناسب است؛ اما به‌تنهایی دسترسی کاربران نهایی به اینترنت یا علت یک اختلال را اثبات نمی‌کند.
- polling باید به API رسمی و با بار معقول محدود بماند؛ از دانلود مکرر کل آرشیو استفاده نمی‌شود.

## 3. RIPE Atlas — فقط نتایج عمومی در فاز نخست

- مستندات API: https://atlas.ripe.net/docs/apis/rest-api-manual/introduction/
- endpointهای خواندن عمومی برای مشاهدهٔ measurementها و probeها بدون احراز هویت در دسترس‌اند.
- ایجاد measurement جدید نیازمند API key و مجوز مناسب است و مصرف آن با سیستم credit محاسبه می‌شود.
- به دلیل سیاست `free_only`، نسخهٔ اول فقط measurementهای عمومیِ موجود را می‌خواند؛ ایجاد measurement جدید تا زمان اثبات امکان انجام رایگان و داشتن credit کافی غیرفعال می‌ماند.
- پوشش جغرافیایی probeها باید برای هر query جداگانه بررسی شود. وجود چند probe در یک کشور، نمایندهٔ همهٔ ISPها یا شهرها نیست.

## 4. OONI — شواهد دسترس‌پذیری و سانسور

- API: https://measurements.ooni.io/
- مستندات داده: https://docs.ooni.org/data
- OONI API برای جست‌وجو و تحلیل اندازه‌گیری‌هاست و برای دانلود انبوه داده طراحی نشده؛ rate limiting دارد.
- صفحهٔ رسمی API از به‌روزرسانی روزانهٔ داده‌ها صحبت می‌کند؛ بنابراین OONI در فاز اول منبع لحظه‌ای ۵ دقیقه‌ای محسوب نمی‌شود.
- از API با نرخ کم استفاده می‌شود. برای تحلیل انبوه، باید روش رسمی raw-data یا dumpهای معرفی‌شده توسط OONI بررسی شود.
- دادهٔ OONI یک شاهد مهم است، اما نتیجه‌ها باید همراه با نوع تست، محل probe، زمان، وضعیت آزمون و احتمال false positive نمایش داده شوند.

## 5. M-Lab — دادهٔ کیفیت و تاریخچه

- FAQ: https://www.measurementlab.net/frequently-asked-questions/
- Dataset: https://www.measurementlab.net/data/ndt/
- داده‌های منتشرشدهٔ M-Lab تحت CC0 منتشر می‌شوند و برای روندهای بلندمدت سرعت و کیفیت اتصال مفیدند.
- این منبع برای داشبورد زندهٔ لحظه‌ای طراحی نشده؛ در ابتدا فقط برای تحلیل batch و مقایسهٔ تاریخی بررسی می‌شود.
- قبل از استفاده از هر فیلد باید privacy policy و schema داده مطالعه شود؛ به‌ویژه اینکه داده‌های خام برخی آزمون‌ها ممکن است شامل IP عمومی باشد. اطلاعات شخصی یا شناسهٔ خام کاربران نباید در داشبورد عمومی بازنشر شود.

## 6. Cloudflare Radar — منبع اختیاری با محدودیت مجوز

- مستندات: https://developers.cloudflare.com/radar/
- API رایگان معرفی شده است، اما دادهٔ endpointهای Radar تحت مجوز CC BY-NC 4.0 منتشر می‌شود.
- به دلیل شرط NonCommercial، این منبع وارد pipeline اصلی نمی‌شود تا کاربرد و مدل انتشار NetGuard از نظر مجوز بررسی و ثبت شود.
- رایگان‌بودن API به معنی مجازبودن هر نوع استفاده یا بازنشر نیست.

## 7. قواعد پذیرش منبع جدید

هر منبع قبل از فعال‌شدن باید این موارد را ثبت کند:

1. مالک و لینک مستندات رسمی؛
2. نوع داده و محدودهٔ جغرافیایی واقعی؛
3. زمان نمونه‌برداری و تأخیر انتشار؛
4. نرخ درخواست مجاز و محدودیت‌ها؛
5. مجوز استفاده، ذخیره‌سازی، بازنشر و انتساب؛
6. نیاز به token، API key یا credit؛
7. قالب داده، schema و نسخهٔ API؛
8. روش تشخیص دادهٔ تکراری و مفقود؛
9. روش ثبت health و خطای منبع؛
10. cadence و retention پیشنهادی.

## 8. سیاست اندازه‌گیری مستقل NetGuard

اندازه‌گیری مستقل فقط برای مقصدهای عمومی و مجاز، با فهرست هدف محدود، زمان‌بندی کنترل‌شده و نرخ کم انجام می‌شود. آزمون‌های DNS، HTTP(S)، TLS و reachability باید از دادهٔ منبع جدا نگهداری شوند. عدم پاسخ به یک مقصد فقط «شکست آزمون از یک نقطهٔ اندازه‌گیری» را نشان می‌دهد و به معنی خرابی کل دیتاسنتر یا کل شبکه نیست.

برای نسبت دادن نتیجه به استان، شهر یا اپراتور، وجود vantage point معتبر در همان محدوده و metadata کافی ضروری است.
